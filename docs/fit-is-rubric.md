# FIT IS Opponent Rubric Notes

Use this as a compact checklist for opponent materials and report review.

## Items

- Narocnost zadani: correction factor, not a substitute for fulfillment or quality.
- Rozsah splneni pozadavku zadani: map each assignment point to thesis evidence and implementation/result evidence.
- Rozsah technicke zpravy: judge information value and completeness, not only page count. When a validated FIT Theses Checker summary exists for the current rendered PDF, use it for categorical normostrany claims; otherwise avoid categorical scope claims and state only information value or a typed limitation.
- Prezentacni uroven technicke zpravy: structure, clarity, contribution boundaries, method/data/result explanation, and whether strong claims are proportionate to the evidence.
- Formalni uprava technicke zpravy: language, typography, captions, tables, citations, terminology, visible care.
- Prace s literaturou: relevance, nearest comparable work, citation-to-claim support, separation of own and borrowed work, bibliographic completeness, third-party artifacts.
- Realizacni vystup: functionality or verifiability, technical level, documentation, reproducibility, text-code alignment, tests, validation, licensing, third-party/authorship boundaries, and whether implementation claims are backed by code, run/demo evidence, media, or only text.
- Vyuzitelnost vysledku: distinguish demonstrator, prototype, pilot tool, reusable/deployable tool, negative result, and foundation for future work; record deployment evidence or demo-only limitations.
- Celkove hodnoceni: synthesize fulfillment, technical quality, validation, text, difficulty, main risks, and usefulness.
- Otazky k obhajobe: fair, answerable, important, and not a disguised attack.

## Calibration

- Use grade/bod ranges and rationale, not false precision.
- For DP scope calibration, use the thresholds recorded in the current
  `work/theses_checker_summary.json` or an explicit operator/case instruction;
  do not hard-code categorical normostrany ranges without a current source.
- Do not claim non-functionality when the actual issue is unverifiability from available materials.
- Do not make plagiarism, licensing, or novelty accusations without clear evidence.
- Do not turn standard library, framework, platform, template, asset, generated-code, or AI-assisted capability into the student's invented method unless that contribution boundary is evidenced.
- Credit partial experiment evidence that exists, then criticize missing repeatability, metric definitions, data granularity, uncertainty, or unsupported generalization precisely.
- Treat public report length as a grading-communication constraint: use internal evidence to select compact wording, not to paste the audit trail into IS fields.
- Ask whether the grade can be defended before a committee, the student, and another opponent.
